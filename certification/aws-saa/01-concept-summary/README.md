# [AWS] 간단 요약: 핵심 서비스, 글로벌 인프라, 온프레미스

## 1. 핵심 서비스 간단 요약

### EC2 (Elastic Compute Cloud)
컴퓨터를 빌려서 원격으로 접속해 사용하는 서비스
- CPU·메모리 사양(인스턴스 타입)과 OS(AMI)를 골라 가상 서버를 생성
- 필요할 때 늘리고 줄일 수 있고, 사용한 만큼 과금

### RDS (Relational Database Service)
MySQL이나 PostgreSQL 같은 관계형 DB를 직접 설치하고 관리하는 대신, AWS가 제공하는 DB 인스턴스 단위로 빌려 쓰는 서비스
- 지원 엔진: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Aurora 등

### S3 (Simple Storage Service)
파일을 객체(Object) 단위로 저장하는 스토리지 서비스
- 버킷(Bucket)이라는 저장 공간을 만들고, 그 안에 키(Key, 파일 경로 역할)로 객체를 저장
- 용량 제한 없이 저장 가능, 저장한 용량과 요청 수만큼 과금
- 이미지·로그·백업 파일, 정적 웹사이트 호스팅 등에 사용

### Route 53
도메인을 발급하고 관리해주는 서비스 (AWS의 관리형 DNS 서비스)
- 도메인 등록: Route 53에서 구매 가능. 외부(가비아 등)에서 산 도메인도 네임서버만 바꾸면 Route 53 DNS 사용 가능
- 호스팅 영역(Hosted Zone)에 DNS 레코드(A, CNAME, NS 등)를 관리
- 헬스 체크, 라우팅 정책(지연 시간 기반, 가중치 기반, 장애 조치 등) 제공

### DNS
도메인 이름을 IP 주소로 변환해 주는 시스템
- 네트워크에서 컴퓨터끼리는 IP 주소(예: 3.35.10.20)로 통신
- DNS가 사람이 쓰는 도메인 이름(예: kcy.com)을 IP 주소로 바꿔줌
- 서버 IP가 바뀌어도 DNS 정보만 수정하면 사용자는 같은 도메인으로 계속 접속 가능


### ELB (Elastic Load Balancing)
들어오는 트래픽(부하)을 여러 서버로 나눠 적절하게 분배해주는 서비스
- 서버를 2대 이상 가용할 때 필수적으로 도입
- 종류
  - ALB (Application Load Balancer): HTTP/HTTPS, L7 기반 (URL 경로·호스트별 분배)
  - NLB (Network Load Balancer): TCP/UDP, L4 기반, 고성능
  - GWLB (Gateway Load Balancer): 방화벽 등 보안 장비용

### CloudFront
AWS의 CDN(Content Delivery Network) 서비스
사용자와 가까운 서버에서 컨텐츠(파일, 이미지, 동영상 등)를 전달해 속도를 높이는 서비스
- 원본(오리진)이 서울 리전 S3에 있으면, 미국 사용자는 거리가 멀어 응답이 느림
- CloudFront는 전 세계 엣지 로케이션에 컨텐츠를 캐싱(임시 저장)해서,
  사용자가 가장 가까운 엣지에서 받아가게 함
- 동작 방식: 첫 요청은 오리진에서 가져오고 엣지에 저장 → 이후 요청은 엣지에서 바로 응답 (저장 기간은 TTL로 설정)

### Lambda
서버는 AWS가 관리하고, 개발자는 코드만 작성하면 알아서 실행해 주는 서비스
- 이벤트가 발생할 때 실행 (예: S3에 파일 업로드, API Gateway 요청, EventBridge 스케줄)
- 요청 수와 실행 시간만큼 과금, 실행하지 않으면 비용 없음
- 1회 실행 최대 시간은 15분

## 2. 글로벌 인프라

### 리전 (Region)
AWS 데이터센터가 모여 있는 지리적 지역
- 예: 서울 리전 = ap-northeast-2
- 리전끼리는 서로 독립적으로 운영

### 가용성 (Availability)
시스템이 중단 없이 정상적으로 동작하는 시간의 비율
- 보통 % 로 표현 (예: 99.99% = 1년 중 약 52분 중단 허용)
- 고가용성(HA, High Availability): 장애가 나도 서비스가 계속 동작하도록 설계하는 것

### 가용 영역 (Availability Zone)
리전 안에 있는, 서로 분리된 하나 이상의 데이터센터 묶음
- 예: ap-northeast-2a, ap-northeast-2c
- AZ마다 분리되어 있어 한 AZ 장애가 다른 AZ에 영향을 주지 않음

### 다중 AZ (Multi-AZ)
리소스를 2개 이상의 AZ에 나눠 배치하는 구성
- 한 AZ에 장애가 나도 다른 AZ에서 서비스 유지 → 고가용성 확보
- 단점: 리소스가 늘어나므로 비용 증가

### 단일 AZ (Single-AZ)
리소스를 하나의 AZ에만 배치하는 구성
- 장점: 구성이 단순하고 비용이 적음
- 단점: 해당 AZ에 장애가 나면 서비스 전체가 중단

## 3. 온프레미스 & 마이그레이션

### 온프레미스 (On-premise)
서버·네트워크 장비를 직접 구매해 자체 시설(전산실, IDC)에 설치하고 운영하는 방식 (↔ 클라우드)
- 장점: 인프라를 직접 통제 가능
- 단점: 초기 비용 큼, 증설 느림, 유지보수 직접 해야 함, 재해 대비(DR) 구축 부담

### 마이그레이션 (Migration)
기존 시스템을 다른 환경으로 옮기는 작업 (주로 온프레미스 → 클라우드)
